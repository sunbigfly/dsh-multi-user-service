# 2026-10-28 插件完整性检查

检查对象为 `main` 分支的 `@sunbigfly/dsh-multi-user-service@0.1.1` 源码。GitHub Release 与源码分支独立，此记录不表示已经发布新 Release。

## 已核对

- DSH `0.2.1-rc.2`、Linux/WSL、Node.js 24.20.0 下，公开源码的 495 项测试全部通过，没有失败或跳过；开发副本的 499 项测试包含另外的暂停中桥接原型测试。
- 主服务、工具权限归属、执行工具三个 Bundle 入口属于同一安装包，具备中英文名称、简介及图标。
- 公共包名与客户端模块身份一致；保留已有开发身份的显式兼容检查。运行账号、凭据、本地 profile 与验收文件不随源码分发。
- 执行工具使用当前右侧内嵌界面，保留两个子页签、独立分页、草稿、搜索和配置导入导出；说明复用 DSH 原生 Tooltip。
- 工具权限支持黑名单与白名单。新账号默认黑名单，旧白名单继续按原含义读取，管理员授权与个人选择始终取交集。
- Chrome DevTools runner 的会话浏览器桥接仍暂停。安装包不包含该原型，服务入口也未启用；独立 `dsh-browser` 的授权适配继续独立工作。
- 依赖锁统一采用官方 npm registry 地址，保留原版本与完整性校验。依赖安装不执行生命周期脚本。
- 83 个包内文件的导出映射、相对运行时依赖和三个组件的本地化元数据完整；全新目录安装 tarball 后，主入口、执行工具、工具归属、成员 Host 与核心服务五个入口均成功导入。

## 边界

本次检查覆盖源码回归、打包、模块入口和依赖闭合；没有更改运行中的成员账号、模型、凭据或会话，也没有重启生产服务。第三方商城自动准入没有包含在本次检查中，历史记录见 [商城解析边界](store-verification.md#商城解析边界)；其他 DSH 版本与服务端平台尚未验证。
